# An Instrument Made of Light

Light-based instrument and graphic score by Interspecifics  
Type: A/V Installation · Year: 2025  

---

## 1. Concept Overview

**An Instrument Made of Light** is a spatialized audio-visual installation that uses recordings of global protests as the raw material for a light-based instrument.

Audio fragments from marches and demonstrations are retrieved from open archives (e.g. Amnesty International, Cities and Memory, and others). Through spectral analysis, machine learning, DMX-controlled lighting, and computer vision, these recordings are transformed into a **luminous graphic score** that continuously reconfigures both light and sound.

Protest becomes an energetic field: collective memory is activated as vibrating light and sound, in a closed feedback loop between audio, light, and visual score.

---

## 2. System Overview

The work is built as a **cybernetic loop** with four main subsystems:

1. **Audio & ML Analysis Engine (Max/MSP + FluCoMa)**
2. **Autonomous Light Pattern System (Python + OLA + Showtec Net 2/3)**
3. **Computer Vision & Score Extraction (Python or Max/MSP)**
4. **Spectral Configuration & GUI (Max/MSP)**

The loop works as follows:

1. Protest recordings are analyzed and modeled using FluCoMa-based machine learning in Max/MSP.
2. Analysis results steer an **autonomous pattern engine** running on top of OLA, which controls an array of moving lights and kinetic elements via DMX.
3. A camera captures the evolving light configurations; each frame is interpreted by a computer vision system as a **graphic score**.
4. This score is sent back to Max/MSP to reconfigure spectral processing and spatialization of the sound.
5. The active score and audio metadata are displayed in a projected GUI, allowing the audience to see how audio, light, and analysis interact.

## 3. System Architecture

### 3.1. Audio & ML Analysis (Max/MSP + FluCoMa)

- Loads and plays **protest audio fragments** from open archives.
- Uses **FluCoMa** (Fluid Corpus Manipulation) to:
  - Extract features (spectral centroid, MFCCs, loudness, onset density, etc.)
  - Train / run ML models (clustering, classification, similarity)
- Derives:
  - **Descriptors** of each audio fragment
  - **High-level states** (e.g. intensity, crowd density, texture type)
- Sends normalized control messages (via OSC/UDP or similar) to the **Light Pattern System**.

Outputs (examples):

- Feature vectors per fragment
- ML-derived labels / states
- Control streams, e.g.:
  - `/ml_state intensity texture_id pattern_mode`

### 3.2. Autonomous Light Pattern System (Python + OLA + Showtec Net 2/3)

- Built on **Python + OLA (Open Lighting Architecture)**.
- Uses a **Showtec Net 2/3** Art-Net node to output DMX to all fixtures.
- Receives ML and feature information from Max/MSP and uses it to steer an **autonomous pattern engine** that generates evolving light configurations.

**Controlled fixtures (DMX):**

- **4× moving head spotlights**
- **2× moving mirrors**
- **2× rotation platforms** (with speed and direction channels)

Responsibilities:

- Maintain an internal state machine / pattern engine:
  - Pattern families (swarms, pulses, sweeps, rotations, freezes)
  - Transitions triggered by ML states and audio descriptors
- Map pattern states → DMX universes/channels:
  - Pan / tilt curves
  - Dimmer and strobe behaviors
  - Color / gobo selections
  - Rotation speed and direction of platforms
- Send DMX frames via OLA to the Showtec Net 2/3.

---

### 3.3. Computer Vision & Score Extraction (Python or Max/MSP)

- A camera (overhead or frontal) captures the **light field** generated by the fixtures, mirrors, and rotating platforms.
- Each frame is treated as a **graphic score state**.

Responsibilities:

- Preprocess the camera feed (cropping, exposure normalization, thresholding).
- Extract visual descriptors, such as:
  - Light blobs / centroid positions (x, y)
  - Brightness distribution
  - Movement vectors / motion flow
  - Spatial patterns (clusters, symmetry, density)
- Convert each frame into **symbolic score parameters** that can be interpreted musically/spectrally.

Example score parameters:

- `/score/cluster_count`
- `/score/brightness_map`
- `/score/constellation_id`
- `/score/motion_energy`
- `/score/region_activity[0..N]`

These messages are sent back to Max/MSP (via OSC) to drive spectral processing.

> Implementation note: This module can be implemented either in **Python** (OpenCV, etc.) or in **Max/MSP** using Jitter and external CV libraries. The interface and message formats remain the same.

---

### 3.4. Spectral Configuration & GUI (Max/MSP)

- Receives **score parameters** from the Computer Vision system.
- Uses them to reconfigure:
  - Spectral filters
  - Granular or resynthesis parameters
  - Spatialization / routing in the quadraphonic setup
- Maintains the **feedback connection**:
  - Audio → ML analysis → light patterns
  - Light → camera → score → spectral configuration → new audio behaviors

**GUI / Projection:**

- A custom Max/MSP GUI is projected as part of the installation.
- Displays:
  - Current audio fragment metadata:
    - Archive source
    - Location / date
    - Additional contextual information
  - Live score representation:
    - Visual abstraction of the current camera-derived score
    - Active ML / FluCoMa states
    - Light pattern mode / configuration icons or labels
- The GUI makes visible the otherwise opaque processes that affect both light and sound.

## 4. Data Flow (Closed Loop)

```text
1. Audio & ML (Max/MSP + FluCoMa)
   - Load protest recordings
   - Extract features
   - Train + run ML models
   - Send ML states + features → Light Patterns

        ↓

2. Autonomous Light Patterns (Python + OLA + Showtec Net 2/3)
   - Receive ML and feature data
   - Choose / evolve autonomous patterns
   - Control via DMX:
       - 4 moving head spotlights
       - 2 moving mirrors
       - 2 rotation platforms (speed + direction)
   - Generate continuous light configurations

        ↓

3. Computer Vision & Score Extraction (Python or Max)
   - Capture light field with camera
   - Analyze each frame
   - Convert to symbolic score parameters
   - Send score messages → Max/MSP

        ↓

4. Spectral Configuration & GUI (Max/MSP)
   - Use score parameters to shape spectral processes
   - Resynthesize / spatialize in quadraphonic system
   - Update projected GUI: metadata + score
   - Resulting sound feeds back into ML analysis

        ↺ (loop)
